# v0.1.2：直接読込とのトークン使用量比較

[English](README.md) · [測定条件・再現手順](PROTOCOL.md) · [全比較データ](summary.json) · [短い出力の使い方](../../docs/compact-context.md#日本語)

**9つのツール・条件の組合せのうち、6つでトークンが減りました。** 最大はCodex **53.2%減**
（3案件）、Claude Code **48.0%減**（1案件）、Cursor **40.7%減**（3案件）で、いずれも
全文読込を指示した比較対象との結果です。各ツールで検証3条件中の最大を選び、
その条件の2回を合算しています。最も良い1回だけの数値、平均的な削減率、料金・上限消費の削減率ではありません。

測定日は**2026年10月21日**。約28KBの架空英語ノート12件を使いました。この公開版には
同じ測定バッチの**直接読込・現行キットの2方式のみ、36セッション・144ターン**を掲載します。
各ツール・各条件・各方式2回×4ターンで、この2方式の全試行を残しています。
再公開のための再測定は行っていません。元のバッチには掲載しない方式も含まれていました。
キャッシュをリセットしていないため、その実行位置はデータに残しています。

## 現行版の全比較

各総量は2回×4ターンの合計です。右端は各ペアの削減率で、プラスは削減、マイナスは増加。
2回の観測範囲であり、信頼区間ではありません。3案件の2条件ではキットの課題・ルールは
同一です。キット側の総量の違いは別試行のばらつきです。

全文指示でも、実際の動作は完全に統一されていません。Codexは出力の切れを章読込で補完し、
Claudeは片方の試行で再開時に範囲を絞り、もう片方では全文取得を試みました。
Cursorも全文補完や章・部分読込を使い、1回は無関係な9案件を含む12ファイルで見出し検索を
行いました。これらとClaudeの回復済み権限拒否2件も計上しています。全文の純粋な読込コスト
として扱わず、実際のAIの動作として解釈してください。必要章だけを読む比較対象の方が効率的です。

## 正確さ・更新確認・呼出し数

- キット側は**72/72ターンで期待する回答オブジェクトと完全一致**、JSONだけの形式は**63/72**。
  Cursorが説明文を添えた場合も形式違反として残しています。
- 公開する2方式全体は**144/144で完全一致、129/144で厳密なJSON形式**でした。
- 全36セッションで直後の言い換えはツール0回、更新後はtealを取得しました。直接読込でも更新を検知しています。
- キット側18セッションすべてで初回の対象ハッシュ、3ターン目のUNCHANGEDと同一ハッシュ、
  4ターン目の変更ノートだけのCONTENTと新ハッシュを確認しました。
- blue→tealの変更ではバイト数とナノ秒の更新時刻を保持しました。別の回帰テストでは
  抜粋外だけの変更も同じ条件で検出し、方針が章指定で落ちないことも確認します。

各ツールのキット6セッション・24ターンで、CodexとClaudeは各18回、毎回**初回1／直後0／
変更なし1／変更あり1**の取得でした。Cursorは方針や不足章の追加取得を含む22回で、
`--compact`の使用は9回です。追加呼出しもすべて計上し、ルールへの完全な従い方は保証しません。

## 読み取り方

必要な章が既知なら初回から指定し、方針とまとめて取得します。把握済みの内容は再利用し、
再開時は章指定と完全なハッシュを保持して確認します。必要な未読情報を省略して節約した
ことにはしません。必要章だけの直接読込比ではCodexが3.9%増、Cursorが2.2%増、Claudeが31.2%減でした。

架空の定型的な英語ノートから既知の情報を取得する実験です。意味検索、実業務の正確さ、
全体要約を検証したものではありません。Mac CLIでGPT-6.1-sol・Claude Opus 5（medium）、
Composer 2.5（default）を使用。キャッシュを消去せず、起動時の文脈も完全には隔離していません。
2回の観測から一般的な削減率・文字数の境界・Windowsや短文での削減率は結論できません。
